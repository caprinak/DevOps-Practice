## 🛑 Incident Report: Database "Initial Startup" Failure
**Date**: 2026-01-17
**Symptoms**:
- Microservices (`order`, `product`, `customer`, `payment`) failed to start.
- Logs showed: `FATAL: password authentication failed for user "alibou"`.
- Services could not connect to PostgreSQL.

### 🔍 Root Cause Analysis
1.  **Missing Databases**: The PostgreSQL container (`ms_pg_sql`) starts fresh with only a default `postgres` database. It does **not** automatically create the `order`, `customer`, `product`, or `payment` databases required by the microservices.
2.  **Volume State Mismatch**: When we initially tried to fix credentials in `docker-compose.yml`, the old Docker volume persisted the *old* (possibly incorrect) user data, preventing the new configuration from taking effect.

### ✅ Solution Implemented
1.  **Wipe Volumes**: `docker compose down -v`. This deleted the old persistent data, ensuring a clean slate.
2.  **Restart Infrastructure**: `docker compose up -d` created a fresh PostgreSQL container.
3.  **Manual DB Creation**: We manually executed SQL commands inside the container to create the missing databases.

## ❓ FAQ: Database & Persistence

### Q: Why do we need to create the databases manually?
**A:** The microservices expect their specific database (e.g., `order`) to exist before they can connect and create tables (via Hibernate/JPA). The PostgreSQL image only creates one default DB. Without the specific DBs, the connection URL `jdbc:postgresql://localhost:5432/order` fails.

### Q: Do we need to create the DBs every time we start?
**A:** **No.**
- Docker uses **Volumes** to save data. Even if you stop the containers (`docker compose down` or stop PC), the data persists.
- **Exceptions**: You ONLY need to recreate the databases if:
    1.  You run `docker compose down -v` (which deletes volumes).
    2.  You manually delete the `postgres` volume in Docker Desktop.
    3.  You are setting up the project on a completely new computer.

Here is the arsenal of commands used to diagnose and fix the system.

### 1. Docker & Infrastructure
| Command | Purpose |
| :--- | :--- |
| `docker compose down -v` | **The Nuclear Option**. Stops containers AND deletes volumes (data). Use when DB credentials or state are corrupted. |

| `docker ps` | Verify which containers are actually running. |

## ⚠️ Common Pitfalls

### "Connection Refused" in Prometheus
*   **Cause**: Prometheus running in Docker cannot see `localhost` of your host machine.
*   **Fix**: We use `host.docker.internal` in `prometheus.yml` instead of `localhost`.

### "Resilience4j Not Permitted"
*   **Cause**: Circuit breaker is OPEN.
*   **Fix**: Wait for the `waitDurationInOpenState` (usually 5s) or restart the service to reset the state.
